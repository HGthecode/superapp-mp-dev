# 开发前确认（写入 README.md）

**任何新项目、从零改写、或新增一整块业务之前**，必须先与开发者对话确认下列问题，**得到明确答复并写入应用根目录 `README.md` 后**，才能执行 `sa-mp create` / 改页面 / 改 schema / `data push` / `fn push`。

禁止用「先做一版再说」跳过本流程。开发者已书面写在 `README.md` 且内容齐全时，可复述要点请其确认「按此执行」，不必重复提问。

## 必问清单

一次问清（可分多轮，但未齐前禁止动手）。括号内为示例答法，勿替用户编造。

| # | 问题 | 写入 README 位置 |
| --- | --- | --- |
| 1 | **应用名称**（展示标题，中文即可） | 一级标题 `# …` |
| 2 | **一句话简介**（给谁用、解决什么） | 标题下首段 |
| 3 | **主题色** `primaryColor`（主按钮/强调，如 `#2563eb`） | `## 主题` |
| 4 | **页面默认背景色** `backgroundColor`（如 `#ffffff`） | `## 主题` |
| 5 | **副色调** `subColor`（辅助强调，如 `#60a5fa`） | `## 主题` |
| 6 | **C 端功能**（页面/主流程，条列） | `## 功能` → `### C 端` |
| 7 | **是否需要开放平台控制台 `admin/`**（要/不要；要则列菜单与动作） | `## 功能` → `### 控制台` |
| 8 | **登录与会员**（是否必须登录；是否用地址/支付等壳能力） | `## 能力与约束` |
| 9 | **业务数据**（要不要虚拟表/云函数；有则简述实体：商品、订单等） | `## 能力与约束` |
| 10 | **数据环境**（开发默认 `preview`；何时用 `prod`） | `## 能力与约束` |

可选（有则写入，无则写「无」）：

- 品牌语气 / 禁止使用的视觉风格
- 已有 `appid` 或是否新建应用
- 业务域名（第三方 API）
- 参考竞品或截图说明

## 确认话术

问完后汇总成下方 README 草稿，发给开发者：

```
请确认以下内容将写入项目 README.md，回复「确认」后我再开始搭建/改代码：
…
```

仅当开发者明确回复确认（或等价肯定）后，才写入文件并进入下一步。

## README.md 模板

路径：与 `index.html` 同级。进 git；**不打进 zip**（`sa-mp pack` 排除）。

```markdown
# {应用名称}

{一句话简介}

## 主题

- 主题色：{primaryColor}
- 默认页面背景色：{backgroundColor}
- 副色调：{subColor}

## 功能

### C 端

- …

### 控制台

- 无
- 或：订单列表 / 发货 / …

## 能力与约束

- 登录：{需要 / 不需要 / 部分页面需要}
- 壳能力：{地址选择 / 支付 / 无}
- 虚拟表与云函数：{无 / 有：简述实体}
- 数据环境：开发 preview；正式 {说明}
```

示例见平台仓库 `microAppDemo/shopDemo/README.md`。

## 与后续流程的关系

1. 本文件确认并落盘 `README.md`
2. 再 `sa-mp create` / `init`（若尚未建目录）
3. 复杂需求仍须按 SKILL 主文档「先出计划再动手」（表结构、云函数 auth 等）
4. 实现时 UI 配色以 README「主题」为准；功能范围不得擅自扩大
